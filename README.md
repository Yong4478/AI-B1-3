현재 프로젝트인 워크플로우의 제작 툴은 크게 2가지로 파이썬 코드와, MAKE 툴로 나누어지고 있다.
이러한 두가지 툴중 하나를 고르기 위한 작업으로 2가지 방법을 선택하여 나에게 맞는 워크플로우 툴을 결정할 것이다. 

# 1 AI에게 툴에 관한 설명 듣기

사용 LLM: Gemini 3.1 Pro

Q:워크플로우를 위해 MAKE 툴과 파이썬 중 하나를 고르고 싶어. 각 툴의 성능과 장점, 단점을 설명하고 그에 따른 추천을 해줘

A:
MAKE(구 Integromat)와 파이썬(Python)은 둘 다 강력한 자동화 도구지만, **사용 목적, 프로그래밍 숙련도, 유지보수 방식**에서 명확한 차이가 있습니다.

---

### 1. 툴별 핵심 개요

#### **MAKE (노코드/로우코드 시각화 자동화 툴)**

웹 브라우저 상에서 마우스 드래그 앤 드롭으로 **블록(모듈)을 이어 붙여 워크플로우를 시각적으로 구축**하는 SaaS 플랫폼입니다.

* **주요 용도:** Slack, Google Sheets, Notion, Gmail, CRM, OpenAI API 등 다양한 웹 서비스 간의 데이터 연동 및 업무 자동화.

#### **파이썬 (프로그래밍 언어)**

코드를 직접 작성하여 작동시키는 **전천후 프로그래밍 언어**입니다.

* **주요 용도:** 데이터 수집 및 웹 크롤링, 복잡한 데이터 가공 및 분석, 웹 화면 제어(RPA), 로컬 파일 관리, 대규모 백엔드 연동.

---

### 2. 장점 및 단점 비교

| 구분 | **MAKE** | **파이썬 (Python)** |
| --- | --- | --- |
| **장점** | • **빠른 개발 속도:** 코딩 없이 몇 분 만에 워크플로우 완성 가능.<br>

<br>• **직관적 흐름 파악:** 시각적 캔버스로 에러 발생 지점이나 데이터 흐름 한눈에 확인.<br>

<br>• **서버 관리 불필요:** 클라우드에서 실행되므로 24시간 자동 동작 환경 구축이 매우 간편.<br>

<br>• **수천 개의 앱 연동 지원:** API 문서 분석 없이 계정 연동만으로 바로 사용 가능. | • **무한한 자유도:** 개발자가 원하는 모든 조건문, 반복문, 예외 처리 구현 가능.<br>

<br>• **비용 효율성:** 실행 횟수 증가에 따른 플랫폼 이용료 부담이 없음 (무료 운영 가능).<br>

<br>• **고도화된 기능:** 머신러닝, AI 모델 직접 연동, 복잡한 웹 크롤링/Scraping에 압도적.<br>

<br>• **데이터 대용량 처리:** 대용량 Excel/CSV 가공 및 DB 관리에 월등히 유리. |
| **단점** | • **비용 발생:** 작업 실행 건수(Operations)에 비례해 월 구독료 증가.<br>

<br>• **복잡한 로직 한계:** 고도로 복잡한 조건문이나 알고리즘 구현 시 세팅이 복잡해짐.<br>

<br>• **플랫폼 종속성:** MAKE 서비스 장애 발생 시 대응이 불가능. | • **진입 장벽:** 코딩 지식, API 통신(REST API), JSON 구조 이해 필수.<br>

<br>• **배포 및 관리 부담:** 24시간 자동 실행을 위해 AWS, GCP 등 클라우드 서버 설정 필요.<br>

<br>• **유지보수 고통:** 연동하는 웹 서비스의 API 규격이 바뀌면 코드를 직접 수정해 재배포해야 함. |

### 3. 상황별 선택 가이드 (추천)

#### **MAKE를 추천하는 경우**

1. **빠른 구축이 최우선일 때:** "당장 오늘 안에 메일 수신 시 Notion에 정리하고 Slack으로 알림 보내는 기능을 만들고 싶다"
2. **SaaS 웹 서비스 중심 연동일 때:** Google Workspace, Slack, Trello, CRM, Typeform 등 표준 API를 지원하는 앱끼리 데이터를 주고받을 때.
3. **서버 관리 지식이 없을 때:** AWS, Docker, Linux 서버 설정 및 유지보수를 다루기 부담스러울 때.

#### **파이썬을 추천하는 경우**

1. **웹 크롤링이 필요할 때:** API를 제공하지 않는 웹사이트에서 로그인 후 데이터를 긁어와야 할 때.
2. **대용량 데이터 가공이 필요할 때:** 매일 수만 건 이상의 데이터를 엑셀/데이터베이스로 처리해야 할 때.
3. **비용을 절감하고 싶을 때:** 실행 횟수가 너무 많아 MAKE의 월간 Operations 비용이 부담스러울 때.
4. **로컬 환경 제어가 필요할 때:** 내 PC 내부의 특정 폴더를 감시하거나 로컬 프로그램을 직접 조작해야 할 때.

### 💡 최종 가이드

만약 **개발 경험이 적거나, 상용 웹 서비스(SaaS) 간의 연결이 목적**이라면 고민 없이 **MAKE**로 시작하는 것을 추천합니다. 아이디어를 검증하고 업무 생산성을 올리는 속도가 훨씬 빠릅니다.

반대로 **크롤링, 대용량 데이터 분석, 세밀한 로직이나 서버 단에서의 백그라운드 처리**가 주 목적이라면 **파이썬**을 선택하는 것이 장기적으로 훨씬 유리합니다.

이로써 두 툴에 관한 기본적인 정보를 얻음에 따라 두번째 결정 과정을 진행하겠다.

# 전기차 화재 정보 수집 및 정리 워크플로우

주요 목표: 전기차 화재에 대한 정보 부족을 해결함과 동시에 정보를 정리 및 시각화하여 유의미한 데이터를 추출해내는 것을 목표로 함.

주요 사용 AI 1: Gemini 3.1 pro

💡 추천 워크플로우 아키텍처 (개념도)

트리거(Trigger): 8시간마다 자동 실행 (스케줄러)

뉴스 검색(Search): 네이버 뉴스 API 또는 구글 알리미(RSS)로 '전기차 화재' 최신 기사 수집

AI 분석(AI Processing): ChatGPT API를 사용해 기사 본문에서 [장소, 기종, 원인, 인명피해, 피해금액] 추출

데이터베이스(DB): 구글 스프레드시트(Google Sheets)나 노션(Notion)에 표 형태로 자동 기록

통계 요약(Analysis): 누적된 데이터를 바탕으로 가장 많이 불난 기종과 주요 원인을 요약하여 슬랙(Slack)이나 이메일로 전송

🛠️ 방법 1: 노코드(No-Code) 자동화 툴 사용하기 (코딩 없이 만들기)
코딩에 익숙하지 않다면 Make.com이나 Zapier 같은 자동화 툴을 추천합니다.

Step 1: Make.com에서 Timer 모듈을 추가하고 8시간마다 실행되도록 설정합니다.
Step 2: RSS 모듈을 연결해 구글 뉴스에서 '전기차 화재'를 검색한 피드를 가져옵니다.
Step 3: OpenAI (ChatGPT) 모듈을 연결하고 프롬프트를 이렇게 작성합니다.
"다음 뉴스 기사를 읽고 아래 항목을 추출해서 JSON 형식으로 줘: 1. 화재 장소, 2. 차량 기종, 3. 화재 원인, 4. 인명 피해, 5. 피해 금액"

Step 4: Google Sheets 모듈을 연결해 ChatGPT가 뽑아준 데이터를 엑셀 표의 각 열(Column)에 맞게 추가합니다.
Step 5: 구글 스프레드시트의 '피벗 테이블' 기능을 사용하면, 어떤 기종이 가장 많이 탔는지, 원인이 무엇인지 자동으로 통계가 잡힙니다.

💻 방법 2: 파이썬(Python) 코드로 직접 만들기
코딩을 공부하고 계신다면, 파이썬을 이용해 직접 스크립트를 짜보는 것을 강력히 추천합니다!

아래는 전체적인 흐름을 보여주는 파이썬 코드 뼈대(Template) 입니다.
import schedule
import time
import pandas as pd
# 필요한 라이브러리: requests, bs4(크롤링), openai(AI 분석)

def job():
    print("🔄 8시간 주기 워크플로우 시작...")
    
    # 1. 뉴스 데이터 수집 (예: 네이버 뉴스 API 또는 크롤링)
    news_articles = get_latest_news("전기차 화재") 
    
    extracted_data = []
    
    # 2. AI로 정보 추출하기
    for article in news_articles:
        info = extract_info_with_chatgpt(article)
        # info는 딕셔너리 형태: {'장소': '...', '기종': '...', '원인': '...', '인명피해': '...', '피해금액': '...'}
        extracted_data.append(info)
        
    # 3. 표(DataFrame)로 만들고 저장하기
    df = pd.DataFrame(extracted_data)
    df.to_csv("ev_fire_records.csv", mode='a', index=False) # 엑셀 파일로 누적 저장
    print("✅ 표 업데이트 완료!\n", df)
    
    # 4. 통계 분석 및 요약
    analyze_data(df)

def analyze_data(df):
    print("📊 [현재까지의 화재 통계 요약]")
    # 가장 화재가 많이 발생한 기종 찾기
    most_frequent_model = df['기종'].value_counts().idxmax()
    print(f"🔥 가장 화재가 많이 발생한 기종: {most_frequent_model}")
    
    # 주요 화재 원인 요약
    common_causes = df['원인'].value_counts().head(3)
    print(f"🔍 주요 화재 원인 TOP 3:\n{common_causes}")

# 8시간마다 job 함수 실행
schedule.every(8).hours.do(job)

print("타이머가 시작되었습니다. 8시간마다 뉴스를 확인합니다.")
while True:
    schedule.run_pending()
    time.sleep(1)

# 사용 툴 MAKE 확정

이유: 초보도 사용 가능할 정도의 난이도, 워크플로우의 시각화 우수, 타 프로그램과의 뛰어난 호환성과 저렴한 비용, 마지막으로 뛰어나고 시각적으로 확인되는 확장성 또한 선택의 이유이다.

🛠️ 워크플로우 구축 5단계
1단계: 데이터를 담을 '표(그릇)' 만들기
가장 먼저 구글 스프레드시트에 접속해서 새 문서를 만듭니다.

첫 번째 줄(A1~H1)에 다음 항목들을 적어주세요.
수집시간 | 기사제목 | 화재장소 | 차량기종 | 화재원인 | 인명피해 | 피해금액 | 기사링크
튜터의 팁: 이렇게 미리 표를 만들어두면, 나중에 Make.com이 어디에 데이터를 넣어야 할지 쉽게 찾을 수 있어요.
2단계: 8시간마다 뉴스 가져오기 (Trigger)
Make.com에 로그인하고 **[Create a new scenario]**를 클릭합니다.

화면 중앙의 큰 + 버튼을 누르고 RSS를 검색해서 선택합니다.
Watch RSS feed items를 클릭합니다.
URL 칸에 구글 뉴스 검색 주소를 넣습니다. (이 주소가 '전기차 화재' 최신 뉴스를 가져옵니다)
👉 https://news.google.com/rss/search?q=전기차+화재&hl=ko&gl=KR&ceid=KR:ko
시계 모양 아이콘을 눌러 실행 주기를 8 hours(8시간) 로 설정합니다.
3단계: AI로 핵심 정보만 쏙쏙 뽑아내기
이제 가져온 뉴스 기사를 ChatGPT에게 읽히고 원하는 정보만 표 형태로 정리하게 만들 차례입니다.

RSS 모듈 옆에 마우스를 올려 +를 누르고 OpenAI (ChatGPT) 를 검색해 추가합니다.
Create a Chat Completion을 선택합니다.
모델은 저렴하고 똑똑한 gpt-4o-mini를 추천합니다.
Messages 항목을 추가하고, Role은 User, Content(프롬프트)에는 아래 내용을 복사해서 붙여넣으세요.
[AI 프롬프트 작성]
다음은 전기차 화재에 대한 뉴스 기사입니다. 기사 내용을 읽고 아래 항목을 추출해주세요.
기사 제목: (여기에 RSS 모듈의 'Title'을 클릭해서 넣으세요)
기사 내용: (여기에 RSS 모듈의 'Description'을 클릭해서 넣으세요)

반드시 아래와 같은 JSON 형식으로만 답변해 주세요. (정보가 없으면 "확인 불가"라고 적어주세요)
{
"장소": "",
"기종": "",
"원인": "",
"인명피해": "",
"피해금액": ""
}

튜터의 팁: Make.com에서 JSON 모듈(Parse JSON)을 하나 추가해서 OpenAI의 결과물을 연결해주면, 다음 단계에서 데이터를 엑셀에 넣기 아주 쉬워집니다.
4단계: 구글 스프레드시트에 자동 기록하기
AI가 정리한 데이터를 아까 만든 표에 넣을 차례입니다.

+를 누르고 Google Sheets를 검색해 추가합니다.
Add a Row(행 추가) 를 선택합니다.
본인의 구글 계정을 연동하고, 1단계에서 만든 스프레드시트 파일을 선택합니다.
그러면 아까 만든 열(장소, 기종, 원인 등)이 화면에 뜹니다.
각 빈칸을 클릭해서 3단계(AI)에서 뽑아낸 결과물(장소, 기종 등)을 알맞게 매칭(드래그 앤 드롭) 해줍니다.
5단계: 통계 분석 대시보드 만들기 (마무리)

 # 결과 확인

<img width="960" height="1032" alt="image" src="https://github.com/user-attachments/assets/331b510f-5acb-4112-8d30-b5de4574c9f4" />

<img width="960" height="1032" alt="image" src="https://github.com/user-attachments/assets/be02beb9-e00a-4200-ae46-4029b514b73d" />


1. 프로젝트 개요

목적: 구글 뉴스에서 '전기차 화재' 관련 기사를 자동으로 수집하고, AI를 활용해 핵심 정보(장소, 차종, 인명피해 등)를 추출하여 구글 시트에 데이터베이스화하는 자동화 시스템 구축
사용 툴: Make.com (자동화 플랫폼), Google News RSS, OpenAI (ChatGPT), Google Sheets
2. 워크플로우 아키텍처 (5단계 시스템 구축 완료)
현재 Make.com을 통해 다음의 5단계 파이프라인이 에러 없이(✅) 완벽하게 연결되어 작동 중입니다.

[수집] RSS 모듈: '전기차 화재' 키워드의 구글 뉴스 피드에서 최신 기사의 제목, 날짜, 링크(URL)를 실시간으로 감지합니다.
[접속] HTTP 모듈: RSS에서 얻은 기사 링크(URL)로 직접 접속하여 웹페이지의 전체 데이터를 크롤링합니다.
[정제] HTML to Text 모듈: 크롤링한 복잡한 웹페이지 코드(HTML)에서 불필요한 태그를 제거하고 '순수 기사 본문 텍스트'만 정제하여 추출합니다.
[분석] OpenAI (ChatGPT) 모듈: 정제된 기사 본문을 바탕으로 AI가 프롬프트에 따라 핵심 데이터(발생 장소, 화재 차량 종류, 인명피해, 피해금액 등)를 정확하게 추출하고 요약합니다.
[저장] Google Sheets 모듈: AI가 분석한 결과값과 기사 원본 링크, 날짜 등을 지정된 스프레드시트 열(Column)에 자동으로 기록합니다.
3. 주요 문제 해결 (트러블슈팅) 성과
프로젝트 진행 중 발생한 주요 이슈들을 성공적으로 해결하며 시스템의 완성도를 높였습니다.

이슈 1: 구글 시트 데이터 누락 문제

원인: 모듈 간 데이터 매핑(연결) 누락

해결: 구글 시트 모듈 설정에서 각 열(Column)에 RSS의 '제목/링크'와 ChatGPT의 '분석 결과' 변수를 정확히 매핑하여 자동 기록 구현 완료.

이슈 2: AI의 기사 본문 인식 불가 문제 (할루시네이션 방지)

원인: RSS 피드는 기사의 제목과 짧은 요약만 제공하여 AI가 분석할 원본 데이터가 부족함.

해결: HTTP 모듈을 추가 도입하여 기사 원문 페이지를 직접 크롤링하도록 구조를 개선함.
이슈 3: AI의 HTML 코드 해독 오류

원인: HTTP 모듈이 가져온 데이터가 복잡한 HTML 코드 형태로 되어 있어 AI가 본문을 식별하지 못함.

해결: 'HTML to Text (Text Parser)' 모듈을 중간에 삽입하여 순수 텍스트만 AI에게 전달하도록 데이터 정제 과정을 추가함. 이를 통해 AI의 데이터 추출 정확도를 극대화함.

4. 현재 상태 및 향후 계획

현재 상태: 모든 모듈의 연결 및 테스트 실행이 성공적으로 완료되었으며, 최종적으로 구글 시트에 원하는 데이터(장소, 차종, 인명피해 등)가 정확히 입력되는지 검증하는 마지막 테스트 단계에 있습니다.

향후 계획:
ChatGPT 프롬프트 미세 조정(Tuning)을 통해 데이터 추출의 정확도와 출력 양식 최적화
Make.com 스케줄링 기능을 켜서 매일 특정 시간(예: 매일 아침 8시)에 자동으로 워크플로우가 실행되도록 자동화 완성

# 추가 수정 방안

<img width="866" height="869" alt="image" src="https://github.com/user-attachments/assets/83fa8ab5-a751-4d5b-8d44-824ad8ef5839" />


1. 프로젝트 개요 (업데이트)

목적: 구글 뉴스에서 '전기차 화재' 관련 기사를 수집하고, AI를 통해 기사의 성격을 분석하여 '실제 화재 사고'와 '연구/예방 기술' 뉴스로 자동 분류한 뒤, 각각 다른 구글 시트에 맞춤형 데이터베이스를 구축함.
핵심 기술: Make.com 자동화, 웹 크롤링(HTTP), 데이터 정제(HTML to Text), 프롬프트 엔지니어링 및 AI 텍스트 분류(OpenAI), 조건부 라우팅(Router)
2. 고도화된 워크플로우 아키텍처 (6단계 시스템)
기존 단일 파이프라인에서, 데이터의 성격에 따라 경로가 나뉘는 조건 분기(Branching) 아키텍처로 확장되었습니다.

[1단계: 수집] RSS: '전기차 화재' 키워드 뉴스 피드 감지
[2단계: 접속] HTTP: 기사 원문 웹페이지 크롤링
[3단계: 정제] HTML to Text: 불필요한 코드 제거 및 순수 본문 텍스트 추출
[4단계: AI 분석 및 분류] OpenAI (ChatGPT):
기사 본문을 분석하여 [분류] 실제사고 또는 [분류] 연구예방으로 태깅(Tagging)
분류 결과에 따라 맞춤형 정보(사고 장소/차종 vs 연구 기술/기대효과) 추출
[5단계: 조건 분기] Router: AI가 출력한 '[분류]' 태그 키워드를 인식하여 데이터의 이동 경로를 자동으로 결정
[6단계: 맞춤형 적재] Google Sheets (2중 분기):
➡️ (경로 A) 실제 사고: [분류] 실제사고 태그가 있을 경우, '사고 기록용' 시트에 장소, 차종, 인명피해 등 기록
➡️ (경로 B) 연구 및 예방: [분류] 연구예방 태그가 있을 경우, '연구 개발용' 시트에 예방 기술, 기대 효과 등 기록
3. 주요 개선 사항 및 기대 효과

데이터 품질(Quality) 극대화 및 할루시네이션 방지:
기존에는 예방 관련 뉴스에서도 억지로 '사고 장소'를 추출하려다 보니 AI가 엉뚱한 값을 만들어내는 오류(할루시네이션)나 빈칸이 발생했습니다. 이를 해결하기 위해 AI가 먼저 기사의 종류를 판단하게 함으로써, 각 기사 성격에 딱 맞는 정확한 데이터만 추출하도록 시스템을 대폭 개선했습니다.
데이터베이스(DB)의 목적별 분리:
수집된 데이터를 하나의 시트에 섞지 않고, 목적에 따라 두 개의 시트로 분리 적재하여 추후 데이터 분석 및 통계 활용의 편의성을 높였습니다.
4. 최근 트러블슈팅 (문제 해결)

이슈: 프롬프트 고도화 작업 중 AI 모듈로 기사 본문 데이터가 전달되지 않는 현상 발생
원인: 프롬프트 수정 과정에서 이전 모듈(HTML to Text)에서 받아오던 text 변수 매핑이 해제됨.
해결: Make.com의 데이터 흐름을 재실행(Run once)하여 변수를 활성화한 뒤, ChatGPT 프롬프트 내에 text 변수 블록을 재연결하여 AI가 본문을 정상적으로 인식하도록 조치 완료.
5. 현재 상태 및 향후 계획

현재 상태: 조건 분기(Router) 및 필터 설정이 완료되었으며, 기사 성격에 따라 두 개의 구글 시트에 데이터가 정확히 나뉘어 저장되는지 최종 테스트를 진행 중입니다.
향후 계획: 스케줄링(Scheduling) 기능을 활성화하여 시스템을 완전 자동화하고, 일정 기간 데이터를 축적하여 분류 정확도를 모니터링할 예정입니다.
