# 전기차 화재 정보 수집 및 정리 워크플로우

주요 목표: 전기차 화재에 대한 정보 부족을 해결함과 동시에 정보를 정리 및 시각화하여 유의미한 데이터를 추출해내는 것을 목표로 함.

주요 사용 AI 1: Gemini 3.1 pro

💡 추천 워크플로우 아키텍처 (개념도)

트리거(Trigger): 8시간마다 자동 실행 (스케줄러)

뉴스 검색(Search): 네이버 뉴스 API 또는 구글 알리미(RSS)로 '전기차 화재' 최신 기사 수집

AI 분석(AI Processing): ChatGPT API를 사용해 기사 본문에서 [장소, 기종, 원인, 인명피해, 피해금액] 추출

데이터베이스(DB): 구글 스프레드시트(Google Sheets)나 노션(Notion)에 표 형태로 자동 기록

통계 요약(Analysis): 누적된 데이터를 바탕으로 가장 많이 불난 기종과 주요 원인을 요약하여 슬랙(Slack)이나 이메일로 전송

🛠️ 방법 1: 노코드(No-Code) 자동화 툴 사용하기 (코딩 없이 만들기)
코딩에 익숙하지 않다면 Make.com이나 Zapier 같은 자동화 툴을 추천합니다.

Step 1: Make.com에서 Timer 모듈을 추가하고 8시간마다 실행되도록 설정합니다.
Step 2: RSS 모듈을 연결해 구글 뉴스에서 '전기차 화재'를 검색한 피드를 가져옵니다.
Step 3: OpenAI (ChatGPT) 모듈을 연결하고 프롬프트를 이렇게 작성합니다.
"다음 뉴스 기사를 읽고 아래 항목을 추출해서 JSON 형식으로 줘: 1. 화재 장소, 2. 차량 기종, 3. 화재 원인, 4. 인명 피해, 5. 피해 금액"

Step 4: Google Sheets 모듈을 연결해 ChatGPT가 뽑아준 데이터를 엑셀 표의 각 열(Column)에 맞게 추가합니다.
Step 5: 구글 스프레드시트의 '피벗 테이블' 기능을 사용하면, 어떤 기종이 가장 많이 탔는지, 원인이 무엇인지 자동으로 통계가 잡힙니다.

💻 방법 2: 파이썬(Python) 코드로 직접 만들기
코딩을 공부하고 계신다면, 파이썬을 이용해 직접 스크립트를 짜보는 것을 강력히 추천합니다!

아래는 전체적인 흐름을 보여주는 파이썬 코드 뼈대(Template) 입니다.
import schedule
import time
import pandas as pd
# 필요한 라이브러리: requests, bs4(크롤링), openai(AI 분석)

def job():
    print("🔄 8시간 주기 워크플로우 시작...")
    
    # 1. 뉴스 데이터 수집 (예: 네이버 뉴스 API 또는 크롤링)
    news_articles = get_latest_news("전기차 화재") 
    
    extracted_data = []
    
    # 2. AI로 정보 추출하기
    for article in news_articles:
        info = extract_info_with_chatgpt(article)
        # info는 딕셔너리 형태: {'장소': '...', '기종': '...', '원인': '...', '인명피해': '...', '피해금액': '...'}
        extracted_data.append(info)
        
    # 3. 표(DataFrame)로 만들고 저장하기
    df = pd.DataFrame(extracted_data)
    df.to_csv("ev_fire_records.csv", mode='a', index=False) # 엑셀 파일로 누적 저장
    print("✅ 표 업데이트 완료!\n", df)
    
    # 4. 통계 분석 및 요약
    analyze_data(df)

def analyze_data(df):
    print("📊 [현재까지의 화재 통계 요약]")
    # 가장 화재가 많이 발생한 기종 찾기
    most_frequent_model = df['기종'].value_counts().idxmax()
    print(f"🔥 가장 화재가 많이 발생한 기종: {most_frequent_model}")
    
    # 주요 화재 원인 요약
    common_causes = df['원인'].value_counts().head(3)
    print(f"🔍 주요 화재 원인 TOP 3:\n{common_causes}")

# 8시간마다 job 함수 실행
schedule.every(8).hours.do(job)

print("타이머가 시작되었습니다. 8시간마다 뉴스를 확인합니다.")
while True:
    schedule.run_pending()
    time.sleep(1)

1. 프로젝트 개요

목적: 구글 뉴스에서 '전기차 화재' 관련 기사를 자동으로 수집하고, AI를 활용해 핵심 정보(장소, 차종, 인명피해 등)를 추출하여 구글 시트에 데이터베이스화하는 자동화 시스템 구축
사용 툴: Make.com (자동화 플랫폼), Google News RSS, OpenAI (ChatGPT), Google Sheets
2. 워크플로우 아키텍처 (5단계 시스템 구축 완료)
현재 Make.com을 통해 다음의 5단계 파이프라인이 에러 없이(✅) 완벽하게 연결되어 작동 중입니다.

[수집] RSS 모듈: '전기차 화재' 키워드의 구글 뉴스 피드에서 최신 기사의 제목, 날짜, 링크(URL)를 실시간으로 감지합니다.
[접속] HTTP 모듈: RSS에서 얻은 기사 링크(URL)로 직접 접속하여 웹페이지의 전체 데이터를 크롤링합니다.
[정제] HTML to Text 모듈: 크롤링한 복잡한 웹페이지 코드(HTML)에서 불필요한 태그를 제거하고 '순수 기사 본문 텍스트'만 정제하여 추출합니다.
[분석] OpenAI (ChatGPT) 모듈: 정제된 기사 본문을 바탕으로 AI가 프롬프트에 따라 핵심 데이터(발생 장소, 화재 차량 종류, 인명피해, 피해금액 등)를 정확하게 추출하고 요약합니다.
[저장] Google Sheets 모듈: AI가 분석한 결과값과 기사 원본 링크, 날짜 등을 지정된 스프레드시트 열(Column)에 자동으로 기록합니다.
3. 주요 문제 해결 (트러블슈팅) 성과
프로젝트 진행 중 발생한 주요 이슈들을 성공적으로 해결하며 시스템의 완성도를 높였습니다.

이슈 1: 구글 시트 데이터 누락 문제

원인: 모듈 간 데이터 매핑(연결) 누락

해결: 구글 시트 모듈 설정에서 각 열(Column)에 RSS의 '제목/링크'와 ChatGPT의 '분석 결과' 변수를 정확히 매핑하여 자동 기록 구현 완료.

이슈 2: AI의 기사 본문 인식 불가 문제 (할루시네이션 방지)

원인: RSS 피드는 기사의 제목과 짧은 요약만 제공하여 AI가 분석할 원본 데이터가 부족함.

해결: HTTP 모듈을 추가 도입하여 기사 원문 페이지를 직접 크롤링하도록 구조를 개선함.
이슈 3: AI의 HTML 코드 해독 오류

원인: HTTP 모듈이 가져온 데이터가 복잡한 HTML 코드 형태로 되어 있어 AI가 본문을 식별하지 못함.

해결: 'HTML to Text (Text Parser)' 모듈을 중간에 삽입하여 순수 텍스트만 AI에게 전달하도록 데이터 정제 과정을 추가함. 이를 통해 AI의 데이터 추출 정확도를 극대화함.

4. 현재 상태 및 향후 계획

현재 상태: 모든 모듈의 연결 및 테스트 실행이 성공적으로 완료되었으며, 최종적으로 구글 시트에 원하는 데이터(장소, 차종, 인명피해 등)가 정확히 입력되는지 검증하는 마지막 테스트 단계에 있습니다.

향후 계획:
ChatGPT 프롬프트 미세 조정(Tuning)을 통해 데이터 추출의 정확도와 출력 양식 최적화
Make.com 스케줄링 기능을 켜서 매일 특정 시간(예: 매일 아침 8시)에 자동으로 워크플로우가 실행되도록 자동화 완성
